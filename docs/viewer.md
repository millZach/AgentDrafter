# The viewer

The viewer is the browser window where the reviewer watches a drawing set change, steps through its journal, and accepts or undoes (see [`CONTEXT.md`](../CONTEXT.md)). It draws a set's sheets in the page, with the same Rust drawing pipeline that makes the PNG and the PDF, compiled to WebAssembly, with TypeScript and React around it (ADR-0011); the reviewer pans and zooms on a laptop and on a phone. It sits in the [drafting app](drafting-app.md)'s frame ([below](#the-frame)): a ribbon, a tab for each sheet, the drawing as dark model space with the command bar under it, a status bar, and the [assistant's panel](#the-assistants-panel) on the right, its chat beside the journal. A change set an agent sends shows as it lands, named by a toast, its objects marked; the journal steps back through the set as it was; a tap selects an object, whose quick properties open beside it and [edit](#editing-in-quick-properties) its layer, a text's contents, an insert's attribute values and a circle's radius; Undo last and Accept are always in reach; and its first [drawing tools](#drawing-tools), Line, Circle, Rectangle, Text, Move and Erase, draw and edit through change sets, as an agent does; an edit to a template's object is [drawn before it lands](#a-change-set-drawn-before-it-lands) on each sheet it reaches.

## Opening it

`agentdrafter serve` serves the viewer at `/`, beside the HTTP API ([servers.md](servers.md)). Start it in a drawing set's folder and open the address its start line gives under `viewer`:

```
cd examples/demo-plant
agentdrafter serve
{"ok":true,"result":{"address":"127.0.0.1:7316","listening":"http://127.0.0.1:7316","local_only":true,"token_required":false,"viewer":"http://127.0.0.1:7316/"}}
```

The page shows the drawing set in the folder the server started in. Its address can name another, and a sheet: `/?source=examples/demo-plant&sheet=DP-LD-102`, where `source` is a drawing set's folder, a sheet description or a DWG, as the server's folder names it, and `sheet` one of its sheets (the first without it). The address keeps the sheet shown, so a reload shows it again.

**From another machine or a phone**, such as over the tailnet, the server listens on an address beyond the local machine and needs its token:

```
agentdrafter serve --listen 100.101.102.103:7316
{"ok":true,"result":{"address":"100.101.102.103:7316", ... ,"token_required":true,"viewer":"http://100.101.102.103:7316/#token=3f9c…","token":"3f9c…"}}
```

Open the `viewer` address as printed. Listening on `0.0.0.0` prints `http://0.0.0.0:7316/#token=…`: put the machine's own name or address in its place.

## The token

A server listening beyond the local machine refuses every command without its token (`Authorization: Bearer <token>`). The viewer gets it this way:

- The start line's `viewer` address carries the token in its fragment, after `#`. A browser never sends a fragment to a server, so it reaches no server log, no proxy and no `Referer`.
- The page takes it from the fragment once, keeps it in the tab's session storage, and takes it off the address shown with `history.replaceState`, so it is not left in the address bar, the history or a link copied from it. A reload in the same tab keeps working; a new tab needs the address again; the server makes a new token each time it starts.
- The page sends it as `Authorization: Bearer` with every command, and never in a query string. A token in a query string is not taken.
- The start line is the only line the server writes the token in.

The page's own files are served without the token, since a browser cannot send one to open a page: `GET /` (or `/index.html`) and `GET /assets/<file>`, the files `npm run build` wrote, embedded in the binary. They are the page's code and nothing else, no drawing and nothing of the machine's; every drawing comes from a command, which needs the token. Only `GET` and `HEAD` reach them. On the local machine they are served, as commands are, only to a request addressed to the local machine by its `Host` and any `Origin`; the guards of the HTTP API (`Host`, `Origin`, JSON bodies) stay as they are for every command. The page is sent with a Content-Security-Policy that lets it run its own scripts and WebAssembly and talk to its own server only (`default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`), with `Referrer-Policy: no-referrer`. `index.html` is never cached; the assets, whose names carry a fingerprint of their bytes, are cached for good.

## What it draws, and how

The engine stays on the machine that holds the drawings. The page asks it for a sheet with the `display-list` command, which reads the record and lays the sheet out, text in that machine's fonts, and replies with the sheet's display list: the shapes the PNG and the PDF draw from, as JSON, with the set's sheets, the paper and how many millimetres of paper a drawing unit spans. A demo plant loop sheet's reply is about 290 KB: 116 items, 5,582 segments. While Object snap is on, the page asks for the set as it is with `snaps` too, so the reply also gives every object snap of the objects the page draws itself ([below](#object-snaps)): 458 of them on DP-LD-101 and 475 on DP-LD-302, which make the reply 35 and 36 KB larger, about 12%. The set as it is comes with `origins` too ([below](#drawing-tools)): each object says whether its sheet's template or its row writes it, and the reply names the template and every sheet built from it, and on a sheet drawn in a layout the space a new object goes in (`space`), which the template warning and quick properties need; it adds about 30 bytes an object. It comes with `values` too ([below](#editing-in-quick-properties)): each text's contents, each circle's and arc's radius and each insert's attribute values, and where each text value is written; on DP-LD-101 that is 4.4 KB more, about 1.5%. A change set shown before it lands is asked for with the change set (`change_set`) and `origins`, not `values` nor `snaps` ([below](#a-change-set-drawn-before-it-lands)). The page keeps each sheet it has drawn, so going back to a tab asks the server nothing.

The page's renderer, `crates/agentdrafter-viewer`, is Rust compiled to WebAssembly. It reads the reply with the core's own types and draws it with WebGL2:

- **In the display list's order**, as the PNG paints it: a later item covers an earlier one, a blue line over a red one where they cross, a fill over the line under it. Nothing is blended. Items next to one another that draw strokes, or fills, are drawn by one draw call, run after run, and the GPU applies each draw's triangles, and each draw, in order: a demo plant loop sheet, all strokes, is one draw call. A sheet whose strokes and fills alternate more than 64 times is drawn instead in two draws, every item at a depth by its place in the list, a later one nearer, so the depth test keeps the later item's colour in every sample.
- **Strokes**: each segment of each stroke is a quad exactly as wide as its pen and long enough for its round ends, so every pen is as wide as the PNG draws it. The samples the quad's sides cover are the pen's; at a round end the fragment shader works out the share of the pixel the pen covers, by its distance, and that share of the pixel's samples is written (alpha to coverage). Each sample is written opaque, so where one stroke's segments overlap at a corner they cover the same samples once, and the canvas's multisampling, four samples a pixel, smooths the edges.
- **A viewport's contents**, a sheet's model space seen through a viewport of its layout, keep the viewport's window: the stroke shader draws none of a segment's ink outside it, as the PNG cuts it with a mask and the PDF with a clipping path. Fills are cut at the window already.
- **A clipped viewport's contents** draw through the stencil: the boundary's outline, from the display list's `clip_boundaries`, is cut into a fan of triangles from its first corner, which is drawn into the stencil first, each triangle inverting it, leaving it set inside the boundary by the even-odd rule; the viewport's strokes and fills then draw only where it is set, ink, round ends and fills cut at the boundary, as the PNG's mask and the PDF's clipping path cut them. The items seen through one clipped viewport are a run of their own, and a sheet drawn by depth draws them as a span of their own.
- **Fills** (solid hatches, TrueType text) are cut into triangles once, by their fill rule, with [lyon](https://crates.io/crates/lyon_tessellation); the multisampling smooths their edges.
- **Colours** are the [screen colours](../CONTEXT.md): index 7 white on the dark model space, as on AutoCAD's dark screen, where the PNG and the PDF plot it black on white paper. The other standard colours, 1 to 9, show as the picked prototype shows them, lifted where AutoCAD's own would be hard to read on the dark ground (its pure blue, index 5, shows as `#4f7cff`); every other index shows in the colour it plots in. Each segment and fill carries both its screen colour and its colour on paper, and the renderer draws with one or the other: a test's capture draws as the PNG ([below](#measured-against-the-png)). The PNG and the PDF are not touched: the demo plant's are the same, byte for byte, before and after the frame.
- **Pens are widths on paper**, as in the PNG and the PDF: a 0.5 mm pen is twice as wide when the sheet is shown twice as large. The finest pen is one CSS pixel wide, as a PNG's finest is one pixel.
- **Model space** is dark (`#212830`), and the paper is a dashed outline on it, one CSS pixel wide, where the sheet's declared paper ends; a sheet with no paper, such as a DWG, has its outline round its extents with the 5 mm margin a render leaves.
- **The grid**, when Grid is on (F7), draws behind the drawing: a line each quarter inch and a stronger one each inch on a sheet in inches or feet, each 10 mm and each 50 mm on any other. Lines closer than 8 CSS pixels are left out, and zoomed out further the grid steps out ten times as often as it needs. Model space, the grid and the paper's edge are one draw of a quad over the canvas, whose shader works out each pixel, so the grid costs the same at any zoom (`src/grid.rs` spaces it).
- **Panning and zooming** change two numbers the GPU is given; the sheet is laid out once, when it loads. Curves are drawn within a 100,000th of the sheet's larger side, finer than a pixel at the closest zoom.

It needs WebGL2 and nothing newer. It never asks for WebGPU, which Linux's system webview lacks and iPhones have only from iOS 26. A browser without WebGL2 shows that it has none.

## Pan and zoom

As the picked prototype does:

- **Touch**: one finger drags the sheet and flings it on release; two fingers pinch, keeping the point between them under them, and pan as they move; a double tap zooms in where it lands.
- **Mouse and trackpad**: drag to pan; the wheel zooms where the pointer is, as AutoCAD's wheel does; a trackpad's pinch zooms faster; a double click zooms in. Zach decided on 2026-11-11, after trying the viewer, that the wheel zooms.
- **Buttons**: zoom in, zoom out and Fit in a column at the right of the drawing, half way down, as the picked prototype has them; a phone shows only Fit, beside the command bar, where quick properties never cover it.

The sheet can zoom out to half its fitted size and in to 32 times it, and is never flung out of sight.

**The fit.** A sheet is fitted to the screen when it is first shown and on every change of tab: the whole paper, 10 pixels in from the edges, above the command bar (and a phone's bottom sheet under it) and, on a laptop, clear of the zoom buttons. The command bar counts as one line tall, so a prompt that wraps grows over the drawing without moving the fitted sheet. Until the reviewer pans or zooms, the view follows the fit: when the canvas changes size, as a browser may while it settles, or the pixel ratio changes, or the bottom sheet's peek does, the sheet is fitted again. Once the reviewer has moved it, a change of size keeps the point at the middle of the screen where it was, and the fit button fits it again. A fit, or a change of size or tab that fits the sheet, stops a glide still running, so the glide's next frame cannot put back the view it was heading for.

**Line weights.** A line is drawn at its pen's width on paper, so it grows as the sheet is zoomed in, as the plot would look under a magnifier; the thinnest line is one CSS pixel, so it stays visible on a phone. Zach decided on 2026-11-11, after trying the viewer on his phone, to keep lines like paper rather than thin hairlines at every zoom.

## The frame

The viewer sits in the drafting app's frame (#150), built from the prototype Zach picked on 2026-11-18, kept as the tag [`prototype/drafting-app-frame-150`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-frame-150/prototypes/drafting-app-frame): AutoCAD's look, cut down for beginners. On a laptop (900 CSS pixels wide or more), from the top:

- **The title bar**: AgentDrafter, **Undo last** with the change set it would undo, the set and the sheet shown, the status chips, and **Accept…**. The chips say how many change sets are not issued, or which accept issued the set, whether the set is inconsistent, and how many checks fail; stepping back, one amber chip says which entry is shown ([below](#stepping-through-the-journal)).
- **The ribbon**: Draw (Line, Circle, Rectangle, Text) and Modify (Move, Copy, Array, Erase), each tool with its icon and name, and the Layer box. Hovering a tool shows its tip: its name, AutoCAD's alias (`L`, `C`, `REC`, `T`, `M`, `CO` and `CP`, `AR`, `E`) and what it does in plain words; clicking or tapping it, or Enter on it, starts it ([below](#drawing-tools)), and it shows pressed while it runs; clicking it again ends it. The Layer box sets the [current layer](#the-current-layer), with a swatch of the colour it shows in; while an object is selected and no tool runs, it shows that object's layer instead, and a layer picked in it moves the object there ([below](#editing-in-quick-properties)).
- **A tab for each sheet**, with today's dots: inconsistent (!), fails a check (red), or has change sets not issued (blue).
- **The drawing**, dark model space with its grid and the paper's dashed edge. Toasts sit at its top left.
- **The command bar**, under the drawing, prompts in plain words with options to click: `Type a command, such as L for Line, or select an object, or click a snap to read its point` (on a phone, `Pick a tool in Tools, or tap an object to see it; touch and hold to read a point`); `FT-101 selected [ Move Copy Array Erase Clear ]`; `Endpoint of FT-101: 2.3000, 6.5000 in [ Copy as snapped point · Clear ]`; `Showing entry 6 as it was, read-only [ Older Newer Live ]`; `Reaching the server… changes show when it is back`; and a running tool's prompt ([below](#drawing-tools)). It has a field that takes what is typed: on a laptop typing anywhere on the page goes into it, as in AutoCAD; on a phone **⌨ Type** opens it, with the phone's keyboard. Its note says what the keys do now. Over the drawing just above it, the last two lines of what happened: the journal read, a tool's points, a change set sent and landing, a selection, a toggle.
- **The status bar**: a sheet drawn in [several layouts](sheet-description.md#several-layouts) has a tab for each at its left, as AutoCAD's layout tabs are, in the order of AutoCAD's tabs, the first shown first, in a strip that scrolls when there are more than the bar has room for beside its controls; the address names the layout shown, `layout=`, as it names the sheet, and each layout is drawn from its own display list (`display-list --layout`). Then the cursor's place on the drawing in its units, to four decimals (`1.7200, 6.5000 in`), the snapped point's with the snap's name when the cursor holds one ([below](#object-snaps)), never cut short: on a narrow bar the layout strip and the paper give way to it, which follows the view as it moves under a still pointer, as after a fling, the paper and its units (`ANSI B landscape, inches`; paper declared by its size alone, `17 × 11 in`; none, `Extents, inches`), the units as the core gives them; with none from the core, the page cannot tell a drawing that states no unit (a DWG whose INSUNITS is 0) from one whose unit the core does not carry, so it shows no unit word and coordinates with no suffix (`Extents`), never one guessed from the scale, **Grid** (F7), which draws and takes away the grid, **Object snap** (F3), which turns the [object snaps](#object-snaps) on and off, with the ▴ beside it that opens their menu, **Ortho** (F8), which holds Line and Move level or upright ([below](#drawing-tools)), and the connection to the server: live, reaching it, or the entry shown.
- **The side panel** on the right: the [assistant's panel](#the-assistants-panel), its **Chat** first and shown, and the **Journal** beside it.

Escape steps back out of one thing at a time: a text edited on the drawing, a change set drawn before it lands, the Accept dialog, the snaps' menu, a phone's open ribbon, the tool running, what went wrong with what was typed, the selection, then an entry shown.

**On a phone** the drawing keeps the screen. The title bar holds **Tools** and the chips, which wrap onto a second line rather than be cut off; Tools opens the ribbon over the drawing, with Grid, Object snap and Ortho in it, since the status bar is hidden, and tapping a tool folds it again. A sheet's layout tabs are a row under the sheets' tabs. The assistant's panel is a sheet that peeks up from the bottom, dragging up to half or nearly all of the screen by its grip, its peek, the peek's buttons among it (a tap on one is still a tap), or its header; its peek, while it is down, holds the way into the chat, `Ask the assistant…` with the agent's name, in the newest journal entry's place, as the prototype's peek has it (the Journal tab holds every entry), the connection, and Undo last and Accept. Raised, the sheet is the panel itself, and the peek waits under it until it is down again. The command bar sits above the peek, and Fit beside it.

## Watching change sets land

The page watches the set's journal through the server's event stream, `POST /events` ([servers.md](servers.md#watching-a-set)), which sends the `journal` command's reply when it opens and again each time the journal changes on disk. Every change set, failed attempt, undo, accept and discarded proposal adds to the journal, and the stream also sends the [proposals](#proposals) waiting each time one is made, kept or discarded, so the page sees each one whichever process sent it and through whichever interface: an agent's command line in another terminal, its MCP server, the Python library or the HTTP API. A browser's `EventSource` sends no headers, so the page reads the stream with `fetch`, which sends the token as every command does; a stream that ends is opened again, a second later and then more slowly.

For each new entry:

- **The sheets it touched are drawn again**: those a change set landed on, and those of the change sets an undo undid. A sheet shown is asked for at once and drawn in place, keeping the reviewer's view; another is asked for when its tab is opened. A failed attempt and an accept change no file a sheet is drawn from.
- **A toast names it**, as the picked prototype's does: a change set that landed and on which sheets, one that landed on some sheets and failed on others, with the set inconsistent until they are fixed, one that failed whole, one that landed and failed checks, with the first failed check, an undo, and an accept, with the interface it came through. A change set's toast has a Show button, which shows the change.
- **Its objects are marked.** The change set's journal entry names each object it added, changed or moved on each sheet it landed on ([journal.md](journal.md#what-it-records)); on the sheet shown, each gets a halo round what it draws, green for added and amber for changed, which pulses three times as it lands and then holds, as the prototype's do. A deleted object draws nothing to mark.
- **The checks are run again** on the sheets it touched, from the saved files, for the header, the tabs and the toast.

The reviewer looking at the set as it was at an entry ([below](#stepping-through-the-journal)) is not moved: the toast still comes, and Show takes them back to the set as it is. Zach decided this on 2026-11-11, after trying the viewer: the page stays where the reviewer put it when a change set lands, and the toast with its Show button is how they reach it.

**A drawing kept is never older than the sheet.** Each sheet's drawing is kept with its generation: the sheet's version, which each entry that touches it moves on, and an epoch the whole journal shares. A reply that comes after its sheet's version moved on, such as one asked for before a change set to that sheet landed, is not kept, so going back to the sheet asks for it again. A journal that grows shorter, as when a change set's commit is rolled back, or whose entries already seen were replaced, moves the epoch on: every drawing kept, as the set is and as it was at an entry, is dropped and drawn again, and the checks are run again.

## Stepping through the journal

The bottom sheet lists the journal's entries, the newest first: change sets, failed attempts, undos and accepts, each with its number, what it did in a few words, the sheets it landed (✓) and failed (✕) on, its time and what has become of it: landed, failed check, inconsistent, undone, issued, failed attempt, undo or accept, and through which interface. Opening one shows its details: why it failed, its operations, what issued or undid it, and Undo for a change set an undo can take, with every later one.

Stepping to an entry, with the arrows or by opening it, **shows the set as it was just after that entry, read-only**: the page asks `display-list` for the sheet with the entry (`entry`), which the server rebuilds in memory from the undo states and never writes ([journal.md](journal.md#the-set-as-it-was-at-an-entry)). The view moves to a sheet the entry touched and zooms in on its marked objects. **The header's status chip says which entry is shown**: it turns amber and reads `Entry 3 of 5 · Live ›`, and tapping it goes back to live, to the set as it is. Zach chose this on 2026-11-11 from a mock of three places for it, so that nothing is drawn over the drawing, which looks a little warmer (sepia) while it shows the set as it was. Undo last, Accept and each entry's Undo are switched off while stepping, since they act on the set as it is, not the one shown. An entry whose files are no longer kept, because the undo state that held them was pruned (only the 50 newest change sets keep theirs) or the change set was undone, says it cannot be shown, and why, over the drawing.

## Selecting and quick properties

A tap, or a click, selects the object drawn nearest it, within 16 CSS pixels: the core picks it from the display list the page draws, in WebAssembly (`pick` in `src/draw/pick.rs`), so what is selected is what is drawn there, an insert for everything its block draws, and the page holds no hit-test of its own. The selected object gets a blue halo, and its **quick properties** open: on a laptop beside it, to its right or, without room there, to its left, following it as the drawing is panned and zoomed; on a phone as a card above the command bar, at its real height, a wrapped prompt's among it, and above the journal however far it is raised; on a phone held on its side, at the right of the drawing. The object is brought into the part of the drawing the card leaves free, above it or left of it, measured from where the card begins, if the card would cover it. When the journal comes to rest at another height or the command bar changes height, the view moves again only if that newly hides an object that was on the screen and clear of the card; an object the drafter panned away is left where they put it. They show its name, with a swatch of the colour it shows in, the checks it fails, its type (an insert's block), layer, ID, name and block, an insert's attributes, and the change sets that changed it, each of which shows its entry. Its layer, a text's contents, an insert's attribute values and a circle's radius are edited in them ([below](#editing-in-quick-properties)). The selection follows the object by its ID as the sheet is drawn again, so a change set that deletes an object before it leaves it selected; once the object itself is gone, nothing is. A tap on nothing, the card's ×, the command bar's Clear or Escape clears it. The `display-list` reply says what each object is, by its place, which is what quick properties show.

## Object snaps

The cursor catches AutoCAD's [object snaps](../CONTEXT.md) on the drawing, as the prototype Zach picked on 2026-11-18 shows them (#151), kept as the tag [`prototype/drafting-app-snaps-151`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-snaps-151/prototypes/drafting-app-snaps). With no drawing tool running, a snap clicked is read out; a running [drawing tool](#drawing-tools) takes it as its point, and sends it as a snapped point.

**Where the snaps come from.** `display-list` with `snaps` gives every point the core's snap code finds on the objects the page draws itself, the code `query snap` answers with (`crates/agentdrafter-core/src/display_snaps.rs`): each object's own endpoints, midpoints, centres, quadrants, insertion points and nodes, an insert's in its block's geometry, and every intersection between two objects whose geometry's boxes overlap, the geometry as it is and not as a linetype dots it, found through a grid so a sheet of many objects is not every pair, listed once under the earlier object `with` the later. With them come the display list's `edges`, the fills whose edges the nearest snap finds a point on: a polyline's with width, a solid's and a donut's, and no text's or hatch's. The renderer works out each one's outline once, the pieces of its edges with the fill on one side only, so the seams where a wide polyline's segments meet, inside what is drawn, catch nothing. Each names its object by its place, its snap, `which` of its points and, for an intersection, the other object, so a snap here and the same object, snap and `which` asked of `query snap` give the same point, as a test holds on every sheet of the demo plant. Model space seen through a viewport, and objects on a layer that is off or frozen, an object of a block among them, which draw nothing of their own on the page, have none; a clipped viewport snaps on the boundary it is drawn as. The page asks for them only while Object snap is on, and for the sheet again with them when it is turned on; the set as it was at an entry comes without them: it is read-only, and nothing snaps there.

**The nearest snap, with no round trip.** The renderer, `crates/agentdrafter-viewer`, holds the sheet's snaps and, on each move of the mouse, finds those of the running snaps within 12 CSS pixels of the cursor (a finger's 22): nearest first, and of those within 2 pixels of the nearest, AutoCAD's order, endpoint, intersection, midpoint, centre, quadrant, insertion, node, nearest (`src/snapping.rs`). Nearest, when it runs, is the nearest point of what the page draws, found by the core's `nearest` beside `pick`, and is taken only when nothing else is in reach, as it lies everywhere on every object. On a demo plant loop sheet the search takes about 2 microseconds a move. **Tab** steps to the next snap in reach, while the drawing has the keys: from a focused button or field it moves the focus on, as on any page, until a press on the drawing gives it the keys back. Two snaps of one kind at one point are one; at the same place seen from above but at different heights they are two. A click takes the snap at the click itself, found then, not the one the cursor last caught.

**What the drafter sees.** On a laptop the renderer draws AutoCAD's model-space crosshair in place of the arrow, arms of 40 CSS pixels and the pick box in its middle, and the snap's AutoSnap marker in AutoSnap yellow, edged dark: a square for an endpoint, a triangle for a midpoint, a circle for a centre, a diamond for a quadrant, an X for an intersection, two squares for an insertion point, a circled X for a node, an hourglass for the nearest point (`src/overlay.rs`). Beside it the page puts a tag that names the snap and its object, such as `Endpoint · FT-101`, both of an intersection's, and which of the snaps in reach it is when there are several (`2 of 3, Tab`). The status bar's coordinates show the snapped point exactly, with the snap's name, `2.3000, 6.5000 in Endpoint`.

**A snap clicked** with no tool running reads out its point, as AutoCAD's ID command does, and selects its object: the command bar says `Endpoint of FT-101: 2.3000, 6.5000 in [ Copy as snapped point · Clear ]`. **Copy as snapped point** copies the [snapped point](change-sets.md#snapped-points) a change set's operation takes for it, `{"snap": {"id": "DP-LD-101/device", "snap": "endpoint", "which": "objects[3].from"}}`, an intersection's with its `with`; the nearest point, which a snapped point takes only from another snap, and an object with no ID, such as one of a DWG, are read out with no Copy. The read-out and its Copy go when what they name does: another sheet or layout asked for, or an object the point names, its own or an intersection's other, gone from the sheet. A page opened over the tailnet by its address is not a secure context and has no Clipboard API: it copies with the browser's older copy command, which a click still allows, and if that fails too the read-out gives the snapped point in the command bar's history.

**Object snap (F3)** turns snapping on and off. The ▴ beside it on the status bar, or a right-click on it, opens the **Object snap menu**: each snap with its marker and a line on what it means, ticked when it runs, an on/off switch, **Defaults** and **Clear all**. Ticking a snap while snapping is off turns it on. Perpendicular and Tangent are listed under "Inside a drawing tool, from the last point: coming": they will act only in a tool, from its last point, and are not built yet. The **running snaps** by default are Endpoint, Midpoint, Centre and Intersection: AutoCAD's defaults (OSMODE 4133) less Extension, which the core has not got, and with Midpoint, which a beginner reaches for first. Object snap and the running snaps are remembered in this browser, in its local storage (`agentdrafter-object-snaps`), as AutoCAD keeps OSMODE; a private window that keeps nothing keeps them for the visit.

**On a phone**, a finger reaches a snap within 22 CSS pixels. Touch and hold for 350 ms: a magnifier comes up above the finger, the drawing under it three times larger with the crosshair and the marker of the snap it would take, its tag under it, and follows the finger; lifting takes the snap, read out as a click's is, or says there was none under it. A second renderer draws the magnifier, on a canvas of its own, from the same display list. A quick tap still selects, and one finger still pans, once it has moved 6 pixels from where it went down, as a mouse does; a gesture that panned is never also a tap. A finger that moves on more than 3 pixels, short of panning, rests anew where it is, and the magnifier comes 350 ms after that, where the finger is. A second finger puts the magnifier away, with nothing taken, and pinches. A change that lands while a finger is held draws the magnifier anew, and the snap lifted is found again where the finger lifts, on the sheet as it is then and of the snaps running then: Object snap turned off from a keyboard during the hold takes nothing. A finger whose lift comes 350 ms or more after it came to rest, by the events' own times, was held, though a busy page got the lift before its timer: it takes the snap where it lifted, not a tap. A finger is judged by its own events' times, when it moved, not by when the page handled them: on a slow device, where a dragging finger's moves can reach the page after the hold was due, a magnifier that came up meanwhile goes again, with nothing taken, as soon as a move made before the hold was due arrives. The menu is in Tools, under Status, as **Snaps…**.

## Drawing tools

The first drawing tools (#152), built from the prototype Zach picked on 2026-11-19, kept as the tag [`prototype/drafting-app-tools-152`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-tools-152/prototypes/drafting-app-tools): **Line**, **Circle**, **Rectangle**, **Text**, **Move** and **Erase**, as AutoCAD's LINE, CIRCLE, RECTANG, TEXT, MOVE and ERASE run them, cut down for beginners. **Copy** joined them with #66, as AutoCAD's COPY runs, built from the prototype Zach picked on 2026-11-21, kept as the tag [`prototype/drafting-app-copy-66`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-copy-66/prototypes/drafting-app-copy) ([below](#copy)), and **Array**, as AutoCAD's ARRAY runs, rectangular and polar, from the prototype he picked later that day, kept as the tag [`prototype/drafting-app-array-66`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-array-66/prototypes/drafting-app-array) ([below](#array)). Each starts from the ribbon, from its alias typed in the command bar (`L`, `C`, `REC` or `RECTANG`, `T` or `DT`, `M`, `CO` or `CP`, `AR`, `ARRAY`, `ARRAYRECT` or `ARRAYPOLAR`, `E`, in any case), or, for Move, Copy, Array and Erase, from the selected object's command bar options. Enter at an empty prompt starts the last tool again. Another sheet or another layout shown drops the tool running, with nothing sent, since its points were taken on another page. They draw only on a drawing set's sheet as it is: on the set as it was at an entry, a tool goes back to live first, on the object selected there found again by its ID, or on nothing when it is not on the set as it is, and a sheet description or a DWG, which a change set does not edit, says so.

**Where they run.** A tool's steps, its rubber band, its prompts and the change set it gives run in the renderer, `crates/agentdrafter-viewer/src/tools.rs`, in Rust, natively tested; the page passes it the clicks, taps and typing, draws the frame round its prompt, and sends what it gives. What an edit means is the core's: the tool sends one change set through the `change` command, with the operation the core has for what it does, and the core writes the set's records, builds the DWGs and records the change set in the journal, as for an agent's. So Undo last and Accept take a drafter's edit as they take an agent's, and an agent on any interface sees it land.

**What each sends**, one change set when it has what it needs:

| Tool | Steps | Sends |
|---|---|---|
| Line | the first point, then each next point; **Undo** takes the last back, **Close** (after two lines) closes back to the first, **Done**, Enter, Space, a right-click or Esc ends it, keeping what it drew | one `add_line` a segment |
| Circle | the centre, then a point on the circle or a radius typed; **Diameter** takes a diameter typed instead | `add_circle` |
| Rectangle | one corner, then the opposite corner, or its size typed as `@width,height` | a closed `add_polyline` of four points |
| Text | where it starts; **Height** sets its height; then the text, a line at a time, on the drawing on a laptop, Enter for the next line, Enter again or Done to finish; on a phone in a small box, with its height, and **Add** | one `add_text` a line, each line 5/3 of the height under the last |
| Move | the objects, picked one by one (a second pick takes one back) and Enter or Done, or the object selected first; a base point; then where it goes | one `move` an object, `from` the base point `to` the second |
| Copy | the objects, as Move picks them; a base point; then where each copy goes, again and again from the same base point, until Enter, Done or Esc; **Undo**, `U` or Ctrl+Z takes the last copy back | one `copy` of all of them: `from` the base point `to` the second for one copy, `offsets` for several |
| Array | the objects, as Move picks them; then its panel: rectangular rows, columns and spacings, or polar items, angle and a centre clicked; Enter, or **Array**, lands it, Esc sends nothing | one `array` of all of them, `rectangular` or `polar`, with the spacing between items and the angle it fills |
| Erase | the objects, picked, then **Erase N** or Enter, or the object selected first, erased at once | one `delete` an object |

New objects go on the [current layer](#the-current-layer), in the sheet's row, as an object added on one sheet does ([change sets](change-sets.md#where-a-change-lands)), and on a sheet drawn in a layout in the paper space of the layout shown, as `display-list` with `origins` names it under `space`. Move, Copy and Array do not take an object of model space seen through a viewport, whose points on the paper are not its own, and say so; Erase takes it. Text is drawn at 0.12 inches, or 3 millimetres, until a height is typed, which then holds for the session.

**Points.** A click, or a tap, takes the snap the cursor catches there ([object snaps](#object-snaps)), or the point itself, held level or upright with the tool's last point by **Ortho** (F8) in Line, Move and Copy; a snap wins over Ortho, as in AutoCAD. On a phone, touch and hold brings up the magnifier, the rubber band following the finger, and lifting takes the snap under it. The command bar takes a point typed in the sheet's own units: `x,y`; `@dx,dy` from the last point; `@length<angle`, the angle in degrees anticlockwise from the X axis; or, in Line, Move and Copy, a length alone, which goes that far towards the cursor (along X with no cursor), as AutoCAD's direct distance entry. A point clicked on no snap is kept to a ten-thousandth of the unit, as the status bar shows it; one typed, as typed; a circle's radius clicked, to a ten-thousandth too. While a tool takes points the crosshair loses its pick box and two quick clicks or taps are two points, not a zoom; a phone's double tap still zooms when no tool runs.

**Snapped points.** A point taken on a snap goes as a [snapped point](change-sets.md#snapped-points), its object by its ID, the snap, `which` and, for an intersection, `with`, so the core works out the exact place on the sheet as it stands. A Nearest point, and one on an object with no ID, goes as its coordinates. In an edit to a template's object, a snap on a row's own object goes as its coordinates too, since the core refuses a snapped point that is not the same on every sheet the template reaches. A move of several objects goes by coordinates, each point at its own height, a snap's as its snapped point resolves and a point typed relative to another at that one's: the core moves one object after another and would find a snapped point again where the last move put it. One object's move keeps its snapped points, a snap on itself among them, since the core works its `from` and `to` out before it moves it.

**What it shows.** The prompt says what the tool wants, with its options to click (`LINE on wire Click the next point, or type @dx,dy or a length [ Undo · Close · Done ]`), and what went wrong with the last thing typed, in red under it. The rubber band is drawn in the current layer's colour: the line from the last point, the circle and a dashed guide from its centre, the rectangle, and for Move the objects in pale blue where they would go and a dashed guide from the base point; the points taken show as small blue squares, and each object picked has a blue halo. Beside the cursor, as AutoCAD's dynamic input, the length and angle from the last point, a circle's radius (or diameter) or a rectangle's size. A Text tool's lines show where they will go, at their height, in the current layer's colour, with a caret.

**The template warning.** Quick properties say where the selected object **comes from**: its template, which an edit changes on every sheet built from it, or its sheet's row. When the objects Move or Erase picks are a template's, the command bar says so while the tool runs, above its prompt: `This is part of the template. Moving it changes 7 sheets. You will be asked before it lands.` When the tool has what it needs, the change set is [drawn before it lands](#a-change-set-drawn-before-it-lands), on each sheet built from the template, with what would become of each: **Change all 7 sheets** sends the change set, which lands on each of them, all or nothing (ADR-0005); **Cancel** sends nothing. Zach decided the warning on 2026-11-19 from the prototype, and that it shows the change on the drawing, with a band above the command bar, from build 6's. The core says it: `display-list` with `origins` gives each object's `from`, `template` or `row`, and the sheet's `template`, its path and the sheets built from it, as the change set finds them ([servers.md](servers.md)).

**When it lands.** The page asks for the sheets the change set landed on as soon as `change` replies, without waiting for the journal; the journal's event then names it in a toast and marks its objects, as for any change set, and the sheet is not asked for twice. A change set that does not land, or lands on some sheets only, says why in a toast. After a Move, the moved object's snaps come from the core's next display list.

**On a phone** the options are buttons, without the brackets between them, and **⌨ Type** opens the field and the keyboard, for an alias, a point or a length; it is not offered beside a selected object's Move, Copy, Array, Erase and Clear, which a phone gives after the object's name alone, without `selected`, so that the bar stays one line there, nor while the Text tool's box is open.

**While a change set is on its way**, Undo last and Accept wait, since the change set they would take may be about to land, until every change set the page sent has replied; the page sends them one after another, in the order the tools gave them, as when Erase on an object selected first ends a Text tool that kept its words. Once `change` replies, Undo last names the change set, before the journal's event does. The sheets a change set landed on are asked for once, by `change`'s reply or by the journal's event, whichever comes first.

**Keys.** Typing anywhere goes into the command bar's field; Enter enters it, and so does Space inside a tool, with nothing typed, or after a short alias of three letters at most, as in AutoCAD (Space is a space while a text's words are typed, and after any other word, so a sentence can be typed for the [assistant](#the-assistants-panel)); Esc drops what is typed and ends the tool, keeping lines and text it drew, or with nothing changed, while a Text tool's Cancel, and the phone's text box's, drops the line being typed; a right-click on the drawing is Enter, on what is typed, as AutoCAD's; Delete erases the selected object. F3, F7 and F8 work while a tool runs.

### Copy

Copy (#66) is AutoCAD's COPY in its Multiple mode, as Zach picked it on 2026-11-21 from the prototype kept as the tag [`prototype/drafting-app-copy-66`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-copy-66/prototypes/drafting-app-copy), each of its recommended options. It picks objects as Move does, or takes the object selected first, then a base point, `COPY Click a point to copy it from: the base point`, a snap taken as Move takes one. Each point after it **places a copy**, by how far the point is from the base point: clicked, tapped, typed as `@dx,dy` or `@length<angle` from the base point, or a length alone towards the cursor, held by Ortho. The tool then goes on from the same base point, `COPY 2 copies placed, dashed until you finish. Click where the next goes, or type @dx,dy or a length [ Undo · Done: copy 2 ]`, until Enter, Done, a right-click or **Esc**, each of which lands the copies placed, as AutoCAD's COPY keeps them and Line keeps its lines; another tool started lands them too, first, and when they are a template's, and so asked about, it does not start: no tool runs until Change all or Cancel, as none runs while Move's edit is asked about. Leaving them, for an entry of the journal or a proposal opened, drops them with nothing sent, as another sheet or layout shown does. A point on the base point places nothing and says why. **Undo**, `U` or **Ctrl+Z** (⌘Z) takes the last copy placed back; the command bar's note says so, `Enter or Esc: the copies land · Ctrl+Z: one back`. With none placed, Esc, Enter or Done ends the tool with nothing changed. While it runs, the objects stay where they are; the copy that would go where the cursor is follows it dashed in pale blue, with a dashed guide from the base point, as Move's ghost does, and the copies placed show **dashed in the proposal's purple**, each tagged at its top right `copy 1 · waits for Enter`, `copy 1` on a phone: none has landed yet.

**One change set a Copy command.** The copies placed land together as one change set with **one `copy` operation** ([change sets](change-sets.md#copy-and-array)): one copy goes `from` the base point `to` its point, each a snapped point where it was taken on a snap, as one object's move goes; several go as `offsets`, each copy's `[dx, dy, dz]` from the base point. So the journal holds one entry, `copy device, 2 copies`, named by the objects' IDs as every line is, and one Undo last takes them all back. Each copy is the core's: an ordinary object with its own ID, `device-1`, `device-2`, written where its source is, an insert keeping its source's attribute values. An object on a locked layer is refused by the core (`locked`), and the toast says so.

**The template warning.** When an object Copy picked is a template's, the command bar says so while the tool runs: `This is part of the template. This copies it on every sheet built from this template: 7 sheets. You will be asked before it lands.`, or with one sheet built from it, `This copies it in the template, which only this sheet is built from.` Placing a copy asks nothing: the change set is asked about once, when the copies land, [drawn before it lands](#a-change-set-drawn-before-it-lands) on each sheet, the band naming it `Copy junction-box, 2 copies`, with **Change all 7 sheets** and Cancel, as Move's is.

### Array

Array (#66) is AutoCAD's ARRAY, rectangular and polar, as Zach picked it on 2026-11-21 from the prototype kept as the tag [`prototype/drafting-app-array-66`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-array-66/prototypes/drafting-app-array), each of its recommended options. It sits after Copy in Modify, among a selected object's options, and in Tools on a phone; `AR` and `ARRAY` start it rectangular, `ARRAYRECT` rectangular and `ARRAYPOLAR` polar. A path array is not in this build: `ARRAYPATH` is no tool's word, so it goes to the [assistant](#the-assistants-panel), and an agent makes one through the core's [`array`](change-sets.md#copy-and-array). It picks objects as Copy does, `ARRAY Click the objects to array, then Enter`, or takes the object selected first, then opens **its panel**: on a laptop beside the objects and their copies, to their right or, with no room there, their left, placed at each draw so it follows the view; on a phone docked above the command bar, the drawing keeping the objects in sight above it.

**The panel** holds the kind, **Rectangular** or **Polar**; the **Spacing**, **Between items**, where it starts, or **Total, divided evenly**; the fields; how many copies it makes, `3 × 2: 5 copies`, or what is wrong, in red; **Cancel** and **Array**. Rectangular takes **Rows**, **Columns**, **Row spacing** (+ up, − down) and **Column spacing** (+ right, − left), or with the total held **Rows, first to last** and **Columns, first to last**, in the sheet's unit. It starts at three rows, each below the last by the objects' height and a little more, rounded up to a quarter of the unit, and one column. Polar takes **Items**, the objects the first; **Angle between**, or with the total held **Angle to fill**, 360 a whole turn, negative clockwise; the **Centre**, clicked or tapped on the drawing, a snap taken as any point is, or typed as `x,y`, with **Pick** to take it again, nothing landing until the new one is taken, since the copies follow the cursor meanwhile; and **Turn the items as they go round**, on until it is unticked. It starts at six items round a whole turn, and asks for its centre first: until it is taken, the copies follow the cursor round where it is, fainter. On a phone a field for a whole number brings up the number pad, and one for a spacing or an angle the full keyboard, since a phone's decimal pad, as an iPhone's, has no minus sign.

**Spacing.** The core takes the spacing between items, and a polar array's angle to fill. Whichever the drafter holds, the other follows, worked out in the renderer, `crates/agentdrafter-viewer/src/array.rs`, not the page (ADR-0007): a total held is divided over the gaps between the rows or the columns and sent as the spacing between them; an angle between items is sent as the angle they fill, the items less one times it, as the copies show; only items that go a whole turn spread evenly, the items times the angle between them a turn, go as the core's whole turn, `angle` left out anticlockwise and `-360` clockwise, so the copies land in the order shown, with their IDs. Items whose last would sit on the objects a whole turn round, such as four 120° apart, which the core would spread 90° apart, are said and not sent. A value typed is sent as typed; one worked out is cleared of the noise dividing leaves past a ten-billionth, as Copy's offsets are, so 1.2 over three gaps goes as 0.4; a field shows it to four places, `0.6667`. Items that go a whole turn still go a whole turn when their number changes: eight 45° apart, made seven, are 51.4286° apart, not 45.

**Typed in the command bar.** While the panel is up the command bar takes values too: rectangular, `rows,columns` (`4,2` or `4x2`) and `@column,row` spacing, or with the total held the distances first to last; polar, once its centre is taken, `items` or `items,angle`, the angle between items or the one to fill as held; and `TO` or `TOTAL` holds the total, `BE` or `BETWEEN` the spacing between items. It says what it would make: `ARRAYRECT 3 rows × 2 columns, rows 0.500 in apart down, columns 1.000 in apart right: 5 copies. Set it in the panel, or type rows,columns or @column,row spacing [ Array: 5 copies · Cancel ]`, `ARRAYPOLAR 8 items round the centre, a whole turn, 45° apart: 7 copies…`, and on a phone `Set it above`. Its note: `Enter: it lands · Esc: nothing is sent`.

**What shows.** While it is set up the objects stay where they are, and each copy is drawn where it would go, turned round a polar array's centre, **dashed in the proposal's purple**, as Copy's copies placed are, with one tag at the top right of them all, `3 × 2 · waits for Enter`, `8 round · waits for Enter` or `5 round, -180° · waits for Enter`, on a phone `3 × 2`. Values that make no array, such as one row and one column, or more than the core's 10,000 copies of all the objects together, draw no copy, and the tag and the panel say why; so does a field left blank or holding what is not a number, which shows as typed: Array is off and Enter lands nothing until it reads. As the panel opens the view comes to the objects and their copies: on a phone always, into the room above the panel; on a laptop when they show smaller than 300 by 240 pixels, up to three times closer than the fit, clear of the panel's room at their right. After that it moves only when a value puts a copy out of sight. A click on the drawing while the panel is up selects nothing, and a double click opens no text, but a click takes a polar array's centre while it is picked.

**One change set an Array.** Only **Enter**, at the prompt or in a field, a **right-click** on the drawing, which is Enter, or **Array** lands it, as one change set with **one `array` operation** ([change sets](change-sets.md#copy-and-array)): rectangular with `rows` and `columns`, and `row_spacing` and `column_spacing` for more than one row or column; polar with `center`, a snapped point where it was taken on a snap, `count`, `angle` when it fills less than a turn, and `rotate: false` when the items do not turn. So the journal holds one entry, `array terminal-2, 3 × 2` or `array tick-1, 8 round`, and one Undo last takes every copy back. Each copy is the core's: an ordinary object with its own ID, written where its source is, an insert keeping its source's attribute values. **Esc**, Cancel, another tool, another sheet or layout asked for, the moment it is asked for, or an entry of the journal or a proposal opened, ends it with **nothing sent**: an array's copies are only shown until it lands, unlike Copy's copies placed, which Esc lands.

**The template warning.** When an object Array picked is a template's, the command bar says so while it is set up: `This is part of the template. This arrays it on every sheet built from this template: 7 sheets. You will be asked before it lands.`, or with one sheet built from it, `This arrays it in the template, which only this sheet is built from.`; on a phone, under the panel, `Part of the template: the copies land on all 7 sheets. You will be asked first.` Enter or Array then [draws it before it lands](#a-change-set-drawn-before-it-lands) on each sheet, the band naming it `Array terminal-2, 3 × 2`, with **Change all 7 sheets** and Cancel, as Move's and Copy's are; no tool starts while it asks. A polar array's centre on a row's own object goes as its coordinates, as every snap on one does in a template edit.

**Where it runs.** Its steps, the panel's values and words, where each copy goes and the change set it gives run in the renderer, `tools.rs` with `array.rs`, natively tested; the page shows the panel from what the renderer gives (`ToolState.array`), in `viewer/src/ArrayPanel.tsx`, and passes it what is typed (`Viewer.tool_array_value`) and pressed; `web.rs` draws the copies, and gives the tag and the box round them all, which the panel goes beside and the view comes to.

### The current layer

The Layer box lists the sheet's layers, as `query layers` gives them, asked for each sheet and again when the box is opened, a locked one and one not shown so marked, and sets the current layer, which every new object goes on, as AutoCAD's current layer. It starts as layer `0`; the page keeps the layer chosen for each drawing set in the browser's local storage (`agentdrafter-current-layer`), and goes back to `0` on a sheet that has not got it; until the sheet's layers come, it is the layer kept. ## Editing in quick properties

Quick properties edit what change sets already change (#153), built from the prototype Zach picked on 2026-11-19, kept as the tag [`prototype/drafting-app-props-153`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-props-153/prototypes/drafting-app-props): an object's **layer**, a text's or an mtext's **contents**, an insert's **attribute values**, and a circle's **radius** or **diameter**, an arc's radius alone. The other rows stay read-only. They are edited on a drawing set's sheet as it is, an object with an ID, and only while the drawing on the canvas is the view asked for: a step back to an entry, or another sheet, whose drawing is still coming leaves the drawing before it on the canvas, and nothing edits it meanwhile. On the set as it was at an entry, a sheet description or a DWG, they show as before.

**An edit lands at once,** on Enter or on leaving the field, as AutoCAD's Quick Properties do; a layer picked lands as it is picked. **Esc** in a field puts the value back and lands nothing. A field left as it shows lands nothing, an unset attribute's default among them, and so does one landed as it showed when it was focused: a radius shown to four decimals, Enter on it untouched, or a field focused and left again before the sheet drawn again shows what it sent. What is typed stays with its object: another object picked shows its own values. While an input method composes, as for Japanese or Chinese, Enter and Esc are its own, to confirm or dismiss a candidate, in the fields and in a text edited on the drawing. Line breaks pasted into a text's one-line contents or an attribute value, which the browser would strip, are refused under the field, as a second line typed is, a lone CR as an LF; a number pasted into a radius or diameter with a line break after it is taken as the number; a paste only checks, and what it gives lands on Enter or on leaving the field, as what is typed does. A value the core would refuse is said under the field and lands nothing: a text with nothing to show, a second line in a text, a radius or diameter that is not a number more than 0. Each edit is **one change set** through `change`, as a drawing tool's is, so Undo last takes it back and an agent on any interface sees it land: the `change` operation for a layer (`{"layer": "wire"}`), contents (`{"contents": "101A+"}`) and a radius (`{"radius": 0.3}`); `set_attribute` for an attribute, with its `occurrence` when its block defines the tag more than once. **A diameter typed sends its radius**, half of it. An mtext's contents take more than one line: Shift+Enter starts the next, Enter lands them.

**Where each value is written** shows under its label before it is edited, and a note under the field says what an edit changes while it is being edited:

| Written | Chip | What an edit changes |
|---|---|---|
| By the template's object | `7 sheets` | The template, and every sheet built from it: [drawn first](#a-change-set-drawn-before-it-lands), on each of them, "Change all 7 sheets" or Cancel. |
| By a row value the template takes | `4 places` | The sheet's [row value](../CONTEXT.md), on this sheet alone, in every place on it the value fills, all of which change: "This sheet's row value WIRE_1. It fills 4 places on this sheet, and they all change. Only this sheet changes." Nothing is asked. |
| By row values the template joins with fixed text, a [list of parts](drawing-set.md#a-rows-value-inside-other-text) | `2 row values` | Each row value the parts hold, on this sheet alone, in every place each fills: "Joined from this sheet's row values PANEL and SLOT and the template's fixed text. | Nowhere: an attribute the template's insert leaves unset, which shows its default | `unset` | The template's insert, so it lands on every sheet built from it: its note says "The template leaves CHECKED unset. Setting it sets it on the template, so it lands on all 7 sheets.", and it is drawn first, on each of them. |

**A text's contents on the drawing.** A double-click on a text or an mtext on a laptop, or a tap on the text already selected on a phone, edits its contents there, as AutoCAD's TEXTEDIT: on a laptop a box over the text, as wide as it shows, that follows it as the view moves, with the same note of where the contents are written; on a phone build 4's small text box, which takes the card's place, with **Done** and **Cancel**. Enter or a click away lands it, Esc puts it back. The command bar says `TEXTEDIT service: type on the drawing. Enter or clicking away applies it, Esc puts it back`. A double-click on anything else zooms in, as before, a double-click across two objects among them. On a phone two quick taps on two objects are two picks, the second selecting its own and opening nothing. The two are the same object by its ID, so a drawing loaded between them that puts another at its place is not taken for it.

**The Layer box** with an object selected and no tool running shows the object's layer, as since build 2, and a layer picked in it moves the object there: one change set, drawn first when the object is the template's. With nothing selected it sets the current layer, as build 4 built it.

**Where it runs.** The fields, their chips and notes, the radius and diameter arithmetic and the change set each edit gives run in the renderer, `crates/agentdrafter-viewer/src/props.rs`, natively tested; the page shows the fields, takes what is typed, and sends what the renderer gives. They come from `display-list` with `values` (ADR-0007): each object's `values`, a text's or mtext's `contents`, a circle's or arc's `radius`, and an insert's `attributes`, each text value with where it is `written`, `own`, `row_value` (with the value's name and how many places it `fills`), `row_values` (a value joined from a list of parts, listing under `row_values` each row value's `name` and the places it `fills`, such as `{"value": "PANEL P1 SLOT 3", "written": "row_values", "row_values": [{"name": "PANEL", "fills": 3}, {"name": "SLOT", "fills": 2}]}`) or `unset` ([servers.md](servers.md)). ## A change set drawn before it lands

An edit to a template's object is drawn before it lands (#154), as the prototype Zach picked on 2026-11-19 draws it on the drawing (its variant B), kept as the tag [`prototype/drafting-app-preview-154`](https://github.com/millZach/AgentDrafter/tree/prototype/drafting-app-preview-154/prototypes/drafting-app-preview). When Move or Erase on a template's objects, or an edit in quick properties or the Layer box that changes the template, has what it needs, the page sends nothing yet: it asks `display-list` for the sheet shown as the change set would leave it, with the change set (`change_set`), and draws that, a [preview](../CONTEXT.md). Nothing is written and nothing goes in the journal until **Change all**. An edit that touches only a row's own object, or a row value, lands at once, as before.

**On the drawing**, as AutoCAD's REFEDIT fades what is not being edited (XFADECTL): the rest of the sheet faded under model space's colour; what the change set adds in green and what it changes in amber, each item at its pen's width, each object in a dashed box; the old place of what it changes faint, with a dashed guide from where it is to where it would go when it only moves, as Move's ghost; what it deletes faint red and struck through; and a red revision cloud round each check the sheet would then fail, as AutoCAD's DWG Compare clouds what differs, with a tag under it, `Would fail: text_on_line`. Only what would draw otherwise is marked: an attribute changed on an insert marks that attribute's text, not the whole insert. A sheet that would refuse it is framed in red, `Refused on DP-LD-202`; one held back by it, dashed grey. Over the drawing at its top right, `DP-LD-301 as it would be · nothing has landed`. The view comes to what it marks on each sheet as it is first shown, closer than the fit by up to 3.2 times, as stepping to a journal's entry does.

**The band**, above the command bar on a laptop, in its place on a phone, says:

- `PREVIEW`, the edit (`Move service`, or quick properties' own words, `title-block CHECKED set to “ZM”`) and its reach, `on 7 sheets`;
- ◀ the sheet shown ▶, and which of them it is, `6 of 7`;
- what would become of the sheet shown: **Would land**, with how many objects it adds, changes and erases there; **Would land, but fails a check**, with the first check it would fail, in the checker's words and its rule, and how many more; **Refused**, and why, in the core's words; or **Held back**, by a sheet that refuses a template edit, which lands on all its sheets or none (ADR-0005);
- a summary of them all: `All 7 would take it, and no check fails.`; `All 7 would take it, but DP-LD-202, DP-LD-301 and DP-LD-302 would then fail a check. You can still change them; Accept warns of failed checks.`; or `Nothing would change. DP-LD-202 would refuse it, so all 7 sheets are held back.`;
- **Cancel**, which lands nothing, puts a quick properties field's value back and shows the sheet it was made on again, in the layout it was made on; and **Change all 7 sheets** (**Change the template** for a template only one sheet is built from), which sends the change set through `change`, as before, and shows that sheet and layout again. While a sheet would refuse it, the button is off and says **Nothing can land**.

**Only on a current preview.** A change set or an undo landing on the set while it is shown, from any interface, makes what the band says old: from the moment the journal's event comes until the sheet shown has been drawn again on the set as it now is, the band says `The set changed: drawing DP-LD-301 as it would be again…` and **Change all** is off. (That the core itself refuses a change set made against an older set is [#186](https://github.com/millZach/AgentDrafter/issues/186).) A sheet that cannot be drawn as it is, such as one whose line names a layer the change set adds, is still previewed: the band says so in the core's words, and with no old places to show, every item of what it changes is marked.

The sheet tabs say what would become of each sheet it reaches, ✓ would land, ! would fail a check, ✕ refused, – held back; a sheet it does not reach is greyed and does not open. ◀ ▶, the arrow keys and the tabs step through the sheets; Esc cancels. The command bar's field lets go as it opens and takes nothing typed while it is shown, so the arrow keys step even straight after Move's last point was typed there. A journal entry clicked while it is shown ends it, landing nothing, and shows the entry. While it is shown, and after it ends until the set as it is has been drawn in its place, nothing is picked or snapped and no tool starts; the command history steps aside on a laptop, and the command bar says `PREVIEW Nothing has landed yet. ◀ ▶, the arrow keys or the tabs show each sheet; Esc cancels` (on a phone, where the band takes the bar's place, `Nothing has landed. ◀ ▶ or the tabs show each sheet`).

**Check again.** The one refusal a dry run reports that can pass a moment later is a sheet whose DWG cannot be written, such as one open in AutoCAD on Windows: the core tries to open it for writing first, as a change set does, and says `it may be open in AutoCAD. Close it and send the change set again`. Then the band offers **Closed it: check again**, which asks for each sheet again. Every other refusal is the records' own, such as a name the sheet already holds, and asking again changes nothing, so it is not offered.

**What the core gives.** `display-list` with `change_set`, the same JSON `change` takes, applies it in memory to the set as it is, by the dry run's own code, and reads the set through the records it would write ([servers.md](servers.md), [change-sets.md](change-sets.md#a-dry-run)). It draws the sheet asked for as they would leave it and gives `preview`: under `change`, the dry run's reply, each sheet it reaches with whether it would take its part or the error why not; under `checks`, the checker's reply on the sheets it would land on, read from the records as it would write them, as `check` reads the saved files; under `objects`, each object it would add, change or delete on each sheet, as its journal entry would name them; and, on the sheet drawn, the places of the display list's items it would add (`added`) and change (`changed`), what each object it would change or delete draws now where it would draw no more (`was`, with its `items`), and a box round each check the sheet would fail (`clouds`): what fails it, or for a sheet it would leave drawing nothing, its paper. The sheet as it is is drawn too, at the same tolerance, so an item that would draw the same is the same and is not marked; when it cannot be drawn, `warning` says why, `was` is empty and every item of what it changes is in `changed`. A preview writes nothing, so it rolls nothing back: on a set whose journal holds a commit that has not finished, or a last line written in part, it is refused (`rollback_failed`), through every interface, and the next other command rolls that back. `change_set` given as `null` is refused, as `change` refuses it, and is never given with `entry`, which the input's schema says too. Every reply carries every sheet's verdict, so the first one marks every tab. Each sheet's preview is kept while it is shown, and dropped, and asked for again, when any change set lands on the set, since it would then apply to another set. On DP-LD-301 with the service text moved into the zone line, the reply the page asks for, with `origins`, grows from 300,212 to 320,438 bytes, 20 KB or 6.7% more: the dry run's reply for seven sheets, the checker's, and the moved text's old place. It takes 121 ms in a release build on forge, against 9 ms without the change set, as it builds every sheet it reaches in memory, as a dry run does, and checks them; a sheet is asked for once while the preview is shown.

**Where it runs.** What is marked and its place, the fade, the highlights, the old places, the strikes and the clouds, are laid out in the renderer, `crates/agentdrafter-viewer/src/preview.rs`, natively tested, and drawn over the ink by `web.rs`; the page shows the band, the tabs' marks and the tags, from the core's reply, in words `frame.ts` works out. What an edit means, whether a sheet would take it, and the checks, are the core's (ADR-0007).

## Undo and accept

Undo last and Accept are in the title bar on a laptop and in the bottom sheet's peek on a phone.

**Undo last** undoes the newest change set an undo can take, through the same `undo` command every interface reaches, as one ([journal.md](journal.md#undo)); the button names it. An issued change set cannot be undone, so after an accept Undo last is off until a change set lands.

**Accept** issues the working revision through the `accept` command ([journal.md](journal.md#accept)). It asks first, as the prototype's does: the page runs the accept as a dry run and shows what it would issue, the change sets and their sheets, and every failed check, or that all checks pass; **Accept and issue** accepts, despite the failed checks it listed, and only if the journal has not moved on since the dialog opened (`newest_seen`). An accept that cannot be made, the set inconsistent, or nothing to accept, says why in a toast and asks nothing. The journal records the accept as the viewer's. Zach decided on 2026-11-11, after trying the viewer, to keep the words **Accept and issue** and, once issued, **Issued (entry N)** in the header: an accept is named by its entry in the journal, and revisions are not lettered.

**An output folder outside the set.** A set whose `output` is outside its folder, such as `../issued`, is issued as any other: its PDFs say so, since their stamps start from the set's template, and so does a PNG or a PDF made from one of its DWGs alone, since each DWG's build mark names its set ([#50](https://github.com/millZach/AgentDrafter/issues/50), [the stamp](render.md#the-stamp)).

A tab shows its sheet at once when the page has drawn it before; the server is asked for each sheet once. Going back to a sheet already drawn shows it with nothing said of the sheet asked for meanwhile, whether that one is still coming (its reply is kept for later) or failed.

## Building it

The page lives in `viewer/`: TypeScript and React, built with Vite. `npm run build` there builds the renderer for WebAssembly (`cargo build -p agentdrafter-viewer --target wasm32-unknown-unknown --profile wasm-release`), makes its JavaScript glue with `wasm-bindgen`, checks the types, and writes the page into `viewer/dist/`. It needs Node 24 or later, the Rust target `wasm32-unknown-unknown` (`rustup target add wasm32-unknown-unknown`) and `wasm-bindgen-cli` of the version `crates/agentdrafter-viewer` pins (`cargo install wasm-bindgen-cli --version 0.2.130 --locked`, or `WASM_BINDGEN` naming the binary).

```
cd viewer
npm ci
npm run build
cd ..
cargo build -p agentdrafter-cli
```

**How the page reaches the binary.** `crates/agentdrafter-cli/build.rs` embeds every file of `viewer/dist/` in `agentdrafter` when it has been built. The built page is not committed: CI's `Viewer` workflow builds it and tests the binary with it. A plain `cargo build` on a machine without Node works: with no `viewer/dist/`, the binary carries a one-page note in its place that says how to build the viewer, and serves every command as before. This keeps generated WebAssembly and JavaScript out of the repository and out of every pull request's diff, and the required CI jobs need no Node. CI's `Windows binary` workflow, not on the merge bar, builds a Windows `agentdrafter.exe` with the page in, on each push to `main` and when asked, for the speed baseline's run on the laptop ([speed.md](speed.md)).

`npm run dev` serves the page from Vite on port 5173 and sends its commands on to `agentdrafter serve` on `127.0.0.1:7316`, for working on the page.

The page's packages, all permissive or MPL-2.0 (ADR-0010): `react`, `react-dom` and `scheduler` (MIT) go into the page; `vite` (MIT) with `rolldown`, `postcss`, `lightningcss` (MPL-2.0) and their helpers, `typescript` (Apache-2.0), `@types/*` (MIT) and `playwright-core` (Apache-2.0) only build and test it. The renderer's crates: `lyon_tessellation`, `lyon_path`, `lyon_geom`, `euclid` (MIT or Apache-2.0), `float_next_after` and `libm` (MIT), and `wasm-bindgen`, `js-sys` and `web-sys` (MIT or Apache-2.0).

### Measured against the PNG

The canvas is drawn at the view and size of `agentdrafter render --scale 1 --dpi <dpi>` of the same sheet, at one device pixel to a CSS pixel, in the paper look, white all round as a PNG's paper is and each colour in the colour it plots in, and read back. A demo plant sheet in the viewer is the set's sheet; its PNG is rendered from its DWG, which draws the same display list point for point. `viewer/e2e/overlap.yaml` is a made-up sheet of colours drawn over one another: a blue line over a red one, a black line over both, a green fill over the three, a red line over that and a yellow fill over part of it. `viewer/e2e/viewport-clip.yaml` is a made-up layout of lines 2.11 mm wide that a viewport cuts, round ends among them; `viewer/e2e/viewport-boundary.yaml` the same lines and a fill cut by viewports clipped to a circle and to a notched polygon; `examples/layout.yaml` is the layout example, and `examples/layouts.yaml`'s second layout, `Wiring`, is drawn as the address asks for it. A check of the layout tabs opens `examples/layouts.yaml` on a phone, finds a tab for each layout, picks the second, and finds it drawn and named in the address; on a laptop, it finds them at the left of the status bar; and with ten layouts (`viewer/e2e/ten-layouts.yaml`, made up) at 900 CSS pixels wide, the strip scrolls and Grid, Object snap, Ortho and the connection stay on the screen.

For every inked pixel of each image (its darkest channel below 192), the nearest pixel of the other image darker than 224 is looked for, within one pixel and within two, as ticket #11 measured the PNG against AutoCAD; and the nearest in the same colour, no channel more than 96 levels off. That is more than anti-aliasing moves an edge pixel, and less than red, blue or green differ from black, or from one another, even at half a pixel's coverage.

The tolerance the test holds:

- 99.9% of each image's ink within one pixel of the other's, and all of it within two;
- 99.7% of it within one pixel in the same colour;
- at most 0.5% of pixels differing by more than 64 levels in any channel;
- a mean difference under 2 levels in 255.

### Smooth on a phone

The `frames` check opens the demo plant's `DP-LD-101` (5,582 segments, one draw call) at phone size with touch and the CPU throttled four times (Chrome's `Emulation.setCPUThrottlingRate`). Through Chrome's own touch events, a finger moving every 8 ms, each event stamped with the time the finger made it, as a real finger's is, however long the page takes to handle each, it pinches out with two fingers, drags with one and lets go moving, and pinches in. It keeps the time of every display frame and of every draw of the canvas in each gesture, and how long each draw call took. It holds:

- every gesture draws the canvas at least 20 times;
- the page's own draw takes a median of 1 ms at most and 95% within 4 ms;
- the point under the fingers stays under them.

With the GPU (`--gl gpu`) it also holds:

- the canvas drawn on at least 60% of each gesture's frames;
- 95% of the times between draws, and between frames, within 20 ms, 99% within 34 ms (one refresh late at most), and none over 100 ms.

In software WebGL (the default without a GPU, and CI's runner) filling the phone's 1170 by 2532 multisampled canvas on the CPU, beside Chrome's own handling of the test's touches, is slower than a phone's GPU, so those times are reported, not held. On forge:
